# Private meal draft service

Run from the repository root with Python 3.12. The server reads the same USDA survey-food index as Android. Offline search and meal composition work on a fresh install without this service.

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r server/requirements.txt
python -m unittest discover -s server -t .
uvicorn server.service:app --host 127.0.0.1 --port 8000
```

## Private deployment

Place the service behind HTTPS on a host you control. Configure the reverse proxy to cap request bodies at 1.25 MB, disable body and Authorization-header logging, and restrict access to the app and MCP routes. The reference rate limiter is per user and worker; use a shared limit at the proxy for multiple workers. Configure environment values using your deployment's secret store.

| Setting | Use |
|---|---|
| `OPENAI_API_KEY` | Server credential for optional OpenAI Responses text and image identification or requested goal suggestions. |
| `NOURISH_MODEL` | Optional vision-capable Responses model supporting structured output. Default `gpt-4.1-mini`. |
| `NOURISH_ACCESS` | JSON object mapping local owner IDs to distinct SHA-256 token digests, e.g. `{"alice":{"app":"<digest>","lookup":"<different digest>"}}`. Generate separate random tokens of at least 32 characters for every owner and role. Removing a digest revokes that grant. |
| `NOURISH_VAULT_KEY` | Base64-encoded random 32-byte AES key held separately from the SQLite file. Preserve this secret across restarts. |
| `NOURISH_VAULT_PATH` | Absolute path in a private, persistent server directory writable by the service account. |
| `NOURISH_HOSTS`, `NOURISH_ORIGINS` | Comma-separated exact public host names (with port where applicable) and HTTPS origins allowed by the MCP transport. |

Generate a bearer token privately with `python -c 'import secrets; print(secrets.token_urlsafe(32))'`. Hash its literal UTF-8 bytes without a trailing newline. Generate the vault secret with `python -c 'import base64,secrets; print(base64.b64encode(secrets.token_bytes(32)).decode())'`. Supply the original **app** token and HTTPS origin in Android Settings → AI connection & personal USDA key.

## Personal USDA lookup

A user can obtain a [USDA key](https://fdc.nal.usda.gov/api-key-signup/) and enter it in Settings. The app sends it only when they tap Save USDA key. The service encrypts it using AES-GCM bound to the authenticated owner. Checking status returns a boolean. Replace or remove the key while connected. Disconnecting a device clears its local access credential. Revoking a compromised USDA key is done with its issuer.

The official MCP SDK serves Streamable HTTP at `https://your-host/mcp/`. Configure a compatible MCP client with that owner's **lookup** bearer credential. The single read-only tool `search_usda_foods(query)` sends the food name and that owner's key to USDA over HTTPS. It returns FDC IDs, names, nutrient amounts and units. The result never includes the key, and the tool cannot read or write the diary. Android drafts use the bundled dataset independently.

Drafts generated by the Android photo/text endpoint are returned directly to the phone. On an explicit Generate request it sends the description and any selected meal photo to OpenAI with `store: false`. Applies are saved locally in Android only after user confirmation. Provider processing is subject to the operator's provider account terms. Backend tests substitute deterministic model and USDA responses. Use real credentials on a private TLS deployment to exercise live upstream requests.

## Connect a chat client

1. Configure a private HTTPS origin and persistent storage for this service. Set `NOURISH_PUBLIC_ORIGIN` to the origin without a path, and include its host in `NOURISH_HOSTS`. Set `NOURISH_DIARY_PATH` to an absolute SQLite file path in a private directory on a persistent volume. Restrict filesystem and backup access to the operator. Use a single deployment with shared durable storage. This release has no public hosted service.
2. Configure an OAuth authorization server supporting discovery, authorization code with PKCE S256, and an RS256-signed access token. Set `NOURISH_OAUTH_ISSUER` to its exact HTTPS issuer and `NOURISH_OAUTH_JWKS` to its HTTPS public signing-key endpoint. Register the resource audience as `https://YOUR-HOST/chat/mcp` and allow scope `nourish.diary.write`. Map the user's stable token `sub` to the same top-level `NOURISH_ACCESS` entry as their phone’s app-token digest. Use the redirect URI shown by the client and the client registration method supported by your issuer. [ChatGPT OAuth guidance](https://developers.openai.com/apps-sdk/build/auth/)
3. In a ChatGPT account/workspace supporting custom MCP apps with write tools, add the remote app using the resource URL and OAuth, then sign in to the configured issuer. The server advertises the issuer through protected-resource metadata. Supply OAuth client credentials in the client’s configuration if the issuer requires them. Limit who may authorize the client through the issuer’s consent policy. [ChatGPT developer mode](https://platform.openai.com/docs/guides/developer-mode)
4. Enable incoming meals on the phone. Try “Here’s my breakfast. Find the ingredients and portions, show my calories and any known minerals, and ask before logging it as one dish.” ChatGPT interprets the attachment and sends structured food names, sources and portions. Corrections replace the prior review. After approval, compare the receipt, date, food and total with the Android diary. Client and account support for write tools must be verified on the deployment you use.

### Storage and access

The diary MCP credential allows searching the bundled catalog, preparing a review and confirming that review for its owner. Removing the owner from the allowlist blocks subsequent calls. Revoking authorization at the issuer stops new access tokens. Already issued JWTs can remain valid until expiry, so use short access-token lifetimes. The phone uses a separate app credential to download that owner’s confirmed meals.

The private SQLite file holds draft ingredients and nutrition, the owner ID and the confirmed meal history. Drafts expire after 30 minutes and expired drafts are purged on the next preparation. Confirming twice returns the original receipt. Confirmed meals remain on the server for reinstallation and additional devices. Local edit and delete operations affect that phone only. Account-wide deletion, two-way edits, hosted PostgreSQL and encrypted backups are follow-up work. Manage disk encryption, backups and retention on your own host. The ChatGPT-side photo stays with the client; only the structured tool inputs reach this endpoint.
